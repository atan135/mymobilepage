# 04 开发约定与常见问题

> 本节是「踩坑手册」与「规范清单」的合集。遇到问题先翻这里。

## 1. 命名规范

### 文件 / 目录

| 类型 | 风格 | 示例 |
| --- | --- | --- |
| Vue 页面组件 | PascalCase + 后缀 `View` | `UserListView.vue` |
| Vue 布局组件 | PascalCase + 后缀 `Layout` | `AdminLayout.vue`、`TabBarLayout.vue` |
| NestJS Module 目录 | kebab-case | `admin-orders/`、`client-banners/` |
| NestJS Controller / Service | kebab-case | `admin-orders.controller.ts` |
| DTO 类 | PascalCase + `Dto` 后缀 | `CreateProductDto`、`QueryOrderDto` |
| Pinia store 文件 | kebab-case | `admin-auth.ts`、`useCartStore` |
| API 封装文件 | kebab-case，前缀 `admin-` / 客户端直接用资源名 | `admin-orders.ts`、`order.ts` |

### 代码标识符

- **TypeScript**：类用 PascalCase；函数、变量用 camelCase；常量用 UPPER_SNAKE
- **权限码**：`<module>:<action>` 全小写，例如 `product:create`、`order:ship`
- **数据库列名**：snake_case（Prisma `@map`），例如 `password_hash` → JS 端 `passwordHash`
- **路由路径**：kebab-case 段，全小写，例如 `/api/admin/announcements`

## 2. Commit 规范

格式：`<type>(<scope>): <subject>`

- **type**：`feat` / `fix` / `refactor` / `chore` / `docs` / `style` / `test`
- **scope**：客户端常用 `client` / `admin`；服务端常用 `server`；多端改动用 `*`
- **subject**：中文，动词开头，不超过 50 字

示例：

```text
feat(admin): 管理员账号 + 登录 + RBAC
feat(admin): 仪表盘
fix(server): 订单状态机不允许从 COMPLETED 退回
chore(*): npm workspaces 引入 admin 子项目
docs: 补齐 Phase 1 文档库
```

每完成一个 roadmap 子模块建议单独一个 commit。Phase 1 整体至少 6~8 个 commit。详见 `summary/admin-roadmap.md` 末尾的「建议的 commit 拆分」。

## 3. 已知坑位（来自 roadmap 与实践）

### 3.1 默认账号密码固定

- 后台 `admin/admin123`、`operator/admin123`
- 移动端 `alice~eve / user123`

> Seed 脚本使用固定密码，未做随机化；README / 文档中已提示但代码里**没有强制提醒改**。**正式上线前必须修改 seed 脚本或删除默认账号**。

### 3.2 后台主题色

- `admin/src/styles/main.css` 已在 `:root` 显式声明 `--el-color-primary` 等品牌主色变量（值 = Element Plus 默认蓝 `#409eff`），并在 `:root[data-theme="dark"]` 下重写暗色版
- `summary/admin-roadmap.md` 标注的「全局样式 + 主题色」任务实际**已落地**，不是占位

### 3.3 移动端登录页

- `client/src/views/LoginView.vue` 底部文案「演示版：任意非空用户名 / 密码均可登录」**已过时**
- 当前真实流程会经 `server/src/auth/auth.service.ts` 的 `AuthService.login` 做 bcrypt 比对，仅 seed 写入的 5 个测试账号（`alice~eve / user123`）能成功登录
- **建议 Phase 2 顺手清理**：删除登录页底部 hint 文案，删除 `client/src/api/request.ts` 中的 mock 注释与未使用的 `delay()` 导出

### 3.4 订单状态机不允许跨级跳

- 状态机表见 `server/src/admin-orders/dto/order.dto.ts` 的 `ORDER_TRANSITIONS`
- 仅允许沿登记的边切换（例如 1 PAID → 2 SHIPPED → 3 COMPLETED，不允许 1 → 3）
- 发货单独走 `PATCH /api/admin/orders/:id/ship`，可覆盖运单（客服改单）

### 3.5 分类删除保护

- `AdminCategoriesService.remove` 在分类下还有商品时直接抛 `ConflictException`
- 必须先迁移商品到其他分类

### 3.6 管理员账号与种子数据冲突

- Seed 会先 `deleteMany` 清空所有 admin 相关表，再写入固定账号
- 如果你手动建过 `adminUser`，seed 后会被清掉，**手动账号会丢失**

### 3.7 JWT Secret

- `JWT_SECRET`（前台）与 `JWT_ADMIN_SECRET`（后台）**必须不同**
- 否则两端的 Token 会互相通过校验，权限隔离失效
- 生产环境务必替换为强随机串（如 `openssl rand -base64 32`）

### 3.8 Vite Proxy 与生产部署

- 代理仅在 `vite dev` 生效
- 生产环境部署必须用 Nginx 等反向代理把 `/api/*` 转发到后端，否则前端静态文件无法跨域调接口

## 5. FAQ

### Q1：后台登录页提示「账号或密码错误」，但我用的是 seed 给的密码？

- 确认执行过 `npm run prisma:seed`
- 确认数据库是 seed 写入的那个库（看 `DATABASE_URL`）
- 确认账号未被禁用：`AdminUser.status = 1` 才是启用

### Q2：前端 ofetch 报 401 一直跳登录页？

- 检查 localStorage 的 `admin-token` 是否过期（默认 7d）
- 检查 `JWT_ADMIN_SECRET` 是否在 server 启动时正确加载（看 server 启动日志）
- 确认后台登录接口走的路径是 `/api/admin/auth/login`（带 `/admin`）

### Q3：移动端首页没数据？

- 确认 seed 已跑
- `client/src/api/request.ts` 注释「所有接口走本地 mock」是早期版本遗留，**与实际不符**——所有 api 文件都已切到真实接口调用，没有 mock 文件
- 检查浏览器 Network 面板，看请求是否真的发到 `http://localhost:5173/api/banners`

### Q4：仪表盘销售趋势没数据？

- 默认查最近 7 天；seed 中的订单分布在 0~8 天前，前几天应有数据
- 检查 `Order.status` 是否落在 `[1, 2, 3]`（待付款不计 GMV）

### Q5：新增后台页面后菜单不显示？

- 在 `admin/src/layouts/AdminLayout.vue` 的 `menuItems` 数组里追加一项
- 同时给路由 `meta.permission` 配上权限码；用户没有该权限时菜单会被 `v-permission` 隐藏

### Q6：新增字段后 admin 列表页不显示？

- Element Plus 表格列在视图文件中显式声明（没有「自动列」机制）
- 在对应 `xxListView.vue` 的 `<el-table-column>` 区域追加一列

### Q7：Phase 2 占位文档怎么用？

- `docs/20-管理后台/08-` 至 `14-` 已预留给 7 个 Phase 2 模块
- 直接编辑对应文件，移除 `[Phase 2 预留]` 标记，补全模板章节即可
- 目录结构与编号不再变动

### Q8：怎么加一个新的权限码？

1. 在 `server/prisma/seed.ts` 的 `ADMIN_PERMISSIONS` 数组里追加字符串
2. 在后台对应 `controller` 的方法上加 `@RequirePermission('your:perm')`
3. 在前端对应 `view` 的按钮上写 `v-permission="'your:perm'"`
4. 重跑 `npm run prisma:seed` 让 `operator` 账号重新拿到权限列表

### Q9：怎么加一个新的管理端接口？

1. 在 `server/src/admin-xxx/` 创建 module + controller + service + dto
2. 在 `server/src/app.module.ts` 的 `imports` 数组里挂上
3. 在 `admin/src/api/admin-xxx.ts` 写 ofetch 封装
4. 在 `admin/src/router/index.ts` 配路由 + `meta.permission`
5. 在 `admin/src/layouts/AdminLayout.vue` 的 `menuItems` 追加菜单

### Q10：怎么给移动端新增一个页面？

1. 在 `client/src/views/` 创建 `XxxView.vue`
2. 在 `client/src/router/index.ts` 配路由 + `meta.requiresAuth`（如需登录）
3. 写 `client/src/api/xxx.ts` ofetch 封装（baseURL 已经是 `/api`）
