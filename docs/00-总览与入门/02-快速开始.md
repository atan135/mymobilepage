# 02 快速开始

> 5 分钟把三端跑起来。

## 0. 环境要求

| 工具 | 版本 |
| --- | --- |
| Node.js | `>= 20`（见根 `package.json` 的 `engines`） |
| npm | 与 Node 一致 |
| PostgreSQL | `>= 13`（项目使用 `provider = "postgresql"`） |

## 1. 安装依赖

仓库是 npm workspaces 结构，根目录一次安装即可：

```bash
npm install
```

这会同时为 `client/`、`admin/`、`server/` 三个子项目安装依赖。

## 2. 配置环境变量

`server/` 通过 `@nestjs/config` 读取 `.env`。在 `server/` 下创建：

```bash
# server/.env
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DBNAME?schema=public"
JWT_SECRET="dev-user-secret"
JWT_ADMIN_SECRET="dev-admin-secret"
JWT_EXPIRES_IN="7d"
JWT_ADMIN_EXPIRES_IN="7d"
PORT=3000
CORS_ORIGINS="http://localhost:5173,http://localhost:5174"
```

> - `JWT_SECRET` / `JWT_ADMIN_SECRET` 前台与后台**必须分开**，否则两端的 Token 会互相通过校验
> - `CORS_ORIGINS` 多个 origin 用英文逗号分隔，留空则回退到 `http://localhost:5173`
> - 生产环境务必将所有 `dev-*` secret 替换为强随机串

## 3. 初始化数据库

```bash
# 生成 Prisma Client + 跑迁移
npm run prisma:migrate

# 写入初始数据（分类 / 商品 / 用户 / 后台角色 / 订单 / 轮播图 / 公告）
npm run prisma:seed
```

Seed 完成后会自动打印：

```
Admin login: username=admin / password=admin123  (SUPER_ADMIN)
Admin login: username=operator / password=admin123  (ADMIN)
User login (client): username=alice~eve / password=user123
```

> Seed 会先清空所有业务表再重新写入。如果数据库已有重要数据，请备份后再执行。

## 4. 启动三端

需要 3 个终端窗口，分别启动：

```bash
# 终端 A：服务端
npm run dev:server
# → http://localhost:3000/api

# 终端 B：管理后台
npm run dev:admin
# → http://localhost:5174

# 终端 C：移动端
npm run dev:client
# → http://localhost:5173
```

也可以并行：

```bash
# bash / zsh
npm run dev:server & npm run dev:admin & npm run dev:client
```

## 5. 端口与代理

| 端 | Vite 端口 | 后端代理 |
| --- | --- | --- |
| `client/` | `5173` | `/api/*` → `http://localhost:3000` |
| `admin/` | `5174` | `/api/*` → `http://localhost:3000` |
| `server/` | `3000` | — |

代理配置位于 `client/vite.config.ts` 和 `admin/vite.config.ts`，开发期无需关心跨域。

## 6. 联调验证

### 后台链路

1. 浏览器打开 `http://localhost:5174`
2. 用 `admin / admin123` 登录
3. 进入「仪表盘」应能看到：
   - 今日订单数（来自 seed 中的 5 单 0d 数据）
   - 今日 GMV（已付款 + 已发货 + 已完成订单金额合计）
   - 待处理订单（状态 = 0 PENDING 的数量）
   - 热销 Top10 表格（按 `Product.sales` 倒序）
   - 销售趋势折线图（默认 7 天）

### 移动端链路

1. 浏览器打开 `http://localhost:5173`
2. 用 `alice / user123` 登录
3. 首页应能看到：3 张轮播图、6 个分类、24 个商品（每分类 4 个）
4. 选一个商品 → 加入购物车 → 结算 → 填写收货人 → 提交订单
5. 切回后台「订单管理」，该订单状态应为「待发货」(1)

### 端到端 happy path

> 详见 `summary/admin-roadmap.md` 的「Phase 1 完成定义」

```
上架商品（admin）→ 下单（client）→ 后台发货（admin）→ 确认收货（client）→ 订单完成
```

## 7. 常用命令速查

```bash
# 构建
npm run build:client
npm run build:admin
npm run build:server

# 预览（构建产物）
npm run preview:client
npm run preview:admin
npm run start:server        # 跑 server 的 dist

# 类型检查
npm run type-check:client
npm run type-check:admin
npm run type-check:server

# Prisma
npm run prisma:generate     # 仅重新生成 Client
npm run prisma:studio       # 打开可视化数据库管理界面
npm run prisma:seed         # 重置并写入初始数据
```

## 8. 排错

| 现象 | 检查点 |
| --- | --- |
| 后台登录 401 | `JWT_ADMIN_SECRET` 是否设置；Token 是否过期 |
| Prisma 迁移失败 | `DATABASE_URL` 是否可连；数据库是否已存在 |
| 端口冲突 | `server/.env` 的 `PORT`、`admin/vite.config.ts` 与 `client/vite.config.ts` 的 `server.port` |
| ofetch 404 | 确认 `baseURL` 是否带 `/admin`（后台）与不带（移动端） |
| 移动端真实接口未返回数据 | `client/src/api/request.ts` 中的 mock 注释是早期遗留，当前所有 api 已切真实调用；检查 Network 面板确认请求真实发出 |
