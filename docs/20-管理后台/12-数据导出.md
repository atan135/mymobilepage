# 12 数据导出

> Phase 2 / 2.5 模块。后台把订单 / 商品 / 库存流水按筛选条件导出为 .xlsx，服务端用 SheetJS（xlsx）生成 Buffer 流式返回。

## 1. 模块定位

运营在 3 个列表页（订单 / 商品 / 库存流水）按需筛选后一键导出 Excel，避免运营手动拷贝汇总数据。

涉及 2 个角色：

- **运营（admin）**：在列表页点「导出 Excel」，弹 dialog 选筛选条件（默认带上当前列表的 status / keyword）
- **系统**：服务端根据筛选条件从数据库拉数据，用 xlsx 库生成 Buffer 通过 StreamableFile 返回

## 2. 涉及数据表

不新增表，只读现有数据：

- `orders` + `users`（订单导出）
- `products` + `categories`（商品导出）
- `inventory_logs` + `products` + `admin_users`（库存流水导出）

## 3. Server 接口清单

### 3.1 三个导出端点（`server/src/admin-exports/`）

| 方法 | 路径 | 权限码 | 文件名规则 |
| --- | --- | --- | --- |
| `GET` | `/api/admin/exports/orders?status&keyword&dateFrom&dateTo` | `export:orders` | `orders[_dateFrom_dateTo]_YYYYMMDD-HHmm.xlsx` |
| `GET` | `/api/admin/exports/products?categoryId&status&keyword` | `export:products` | `products_YYYYMMDD-HHmm.xlsx` |
| `GET` | `/api/admin/exports/inventory-logs?productId&type&keyword&dateFrom&dateTo` | `export:inventory_logs` | `inventory-logs[_dateFrom_dateTo]_YYYYMMDD-HHmm.xlsx` |

所有端点返回：

```
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="<file>.xlsx"
Content-Length: <size>

<binary xlsx bytes>
```

### 3.2 DTO（`dto/export.dto.ts`）

```ts
class ExportOrdersDto {
  status?: 0|1|2|3|4  // 订单状态
  keyword?: string     // 订单号 / 用户名 / 昵称
  dateFrom?: string    // ISO date string
  dateTo?: string      // ISO date string
}
class ExportProductsDto {
  categoryId?: number
  status?: 0|1
  keyword?: string
}
class ExportInventoryLogsDto {
  productId?: number
  type?: 1|2|3|4|5
  keyword?: string
  dateFrom?: string
  dateTo?: string
}
```

所有筛选条件均为可选；不传 = 全量。

### 3.3 实现要点

```ts
// service: JSON → xlsx Buffer
private toXlsx(rows: Record<string, unknown>[], sheetName: string): Buffer {
  const ws = XLSX.utils.json_to_sheet(rows)
  const wb = XLSX.utils.book_new()
  XLSX.utils.book_append_sheet(wb, ws, sheetName)
  return XLSX.write(wb, { type: "buffer", bookType: "xlsx" }) as Buffer
}
```

```ts
// controller: StreamableFile 返回
new StreamableFile(buf, {
  type: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
  disposition: `attachment; filename="${filename}"`
})
```

## 4. 导出字段

### 4.1 订单（17 列）

订单号 / 用户名 / 用户昵称 / 订单状态 / 商品总额 / 优惠金额 / 实付金额 / 收件人 / 收件手机 / 收货地址 / 物流公司 / 物流单号 / 备注 / 创建时间 / 付款时间 / 发货时间 / 完成时间

`receiver` JSON 字段拆成 3 列（收件人 / 手机 / 地址），日期字段统一 `YYYY-MM-DD HH:mm:ss` 格式。

### 4.2 商品（10 列）

商品 ID / 商品标题 / 分类 / 当前售价 / 原价 / 库存 / 阈值 / 已售 / 状态（上架/下架） / 上架时间

### 4.3 库存流水（12 列）

流水 ID / 商品 ID / 商品标题 / 类型（入库/出库/调整/退款入库/取消退库） / 变更数量 / 变更前库存 / 变更后库存 / 原因 / 操作人 ID / 操作人用户名 / 操作人昵称 / 时间

操作人为 null 时填「系统」（客户端自动行为无操作人）。

## 5. Admin 路由与页面

不新增路由，复用现有列表页加导出按钮：

| 列表页 | 文件 | 改动 |
| --- | --- | --- |
| `/orders` | `admin/src/views/OrderListView.vue` | 顶部「导出 Excel」按钮（`v-permission="export:orders"`） + Dialog |
| `/products` | `admin/src/views/ProductListView.vue` | 同上（`v-permission="export:products"`） |
| `/inventory/logs` | `admin/src/views/InventoryLogListView.vue` | 同上（`v-permission="export:inventory_logs"`） |

### Dialog 行为

- 打开时**默认带上当前列表的 status / keyword**，日期范围默认为空
- 用户改完条件点「导出」→ 调 ofetch（`responseType: "blob"`）→ 触发浏览器下载
- 文件名优先用服务端 `Content-Disposition` 的 `filename`，缺失则降级为客户端 `xxx.xlsx`

API 封装：`admin/src/api/admin-exports.ts`，导出 3 个 `async function` + 一个 `triggerDownload` 工具。

## 6. 关键流程

```mermaid
sequenceDiagram
    participant A as 运营
    participant AD as AdminListView
    participant AX as admin-exports.ts
    participant SV as AdminExportsService
    participant DB as PostgreSQL

    A->>AD: 点「导出 Excel」 + 选筛选
    AD->>AX: exportXxx(params)
    AX->>SV: GET /api/admin/exports/xxx?params (raw blob)
    SV->>DB: findMany (按筛选条件)
    DB-->>SV: rows[]
    SV->>SV: rows.map(...) + json_to_sheet
    SV-->>AX: xlsx Buffer (Content-Disposition)
    AX->>A: a.download = filename; a.click()
```

## 7. 权限点

| --- | --- | --- |
| `export:orders` | 订单导出接口 + 按钮 | ✓ |
| `export:products` | 商品导出接口 + 按钮 | ✓ |

## 8. 演示版简化

- **不分批**：当前实现 `findMany` 不带 `skip/take`，demo 数据 < 1000 行无压力；生产环境数据量大时应分批写入 Sheet
- **不入审计日志**：导出动作暂不写 AuditLog（与 2.6 模块一起补）
- **同步生成**：服务端是同步返回 Buffer，不是流式分块；量大时会阻塞

## 9. 关联

- 数据来源：与 2.5 / 2.4 / 2.2 模块的列表接口完全一致，只是改返回格式
- 后续 2.6 操作日志模块可加「导出」作为审计动作，自动捕获 GET 出口
