# 04 移动端核心业务流程

> 三个最关键的业务流程：登录、下单（结算）、确认收货。每个流程含时序图、关键校验点、相关表 / 接口。

## 1. 登录流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant V as LoginView
    participant S as useUserStore
    participant API as /api/auth/login
    participant DB as PostgreSQL

    U->>V: 输入用户名 + 密码
    V->>S: userStore.login({ username, password })
    S->>API: POST /api/auth/login
    API->>DB: 校验 user + bcrypt(passwordHash)
    DB-->>API: user
    alt 校验通过
        API-->>S: { token, user }
        S->>S: localStorage.setItem('token', token)<br/>localStorage.setItem('user', user)
        S-->>V: 成功
        V->>V: router.replace(route.query.redirect ?? '/home')
    else 校验失败
        API-->>S: 401
        S-->>V: error → showToast('账号或密码错误')
    end
```

要点：

- 实际走 NestJS `AuthService.login`：`bcrypt.compare(dto.password, user.passwordHash)`，密码错误抛 `UnauthorizedException('用户名或密码错误')`
- **真实版**：服务端走 `AuthService.login`，bcrypt 比对 `User.passwordHash`，签发 JWT（`JWT_SECRET`）
- 登录后路由：跳回 `route.query.redirect`（来自全局守卫带的），默认 `/home`

## 2. 下单（结算）流程

两个入口：

- **入口 A：购物车结算** — CartView → 「结算」→ OrderConfirmView（多商品）
- **入口 B：立即购买** — ProductDetailView → 「立即购买」→ OrderConfirmView（单商品，URL 带 `?productId&quantity`）

```mermaid
sequenceDiagram
    participant U as 用户
    participant CV as CartView / ProductDetail
    participant OC as OrderConfirmView
    participant P as useCartStore
    participant API as /api/orders
    participant DB as PostgreSQL

    Note over U,CV: 入口 A：购物车
    U->>CV: 选商品 + 点「结算」
    CV->>OC: router.push('/order/confirm')
    OC->>P: cart.selectedLines()
    P-->>OC: lines (productId + quantity)
    loop 每个 line
        OC->>API: GET /api/products/:id (拿最新价格/库存)
        API-->>OC: product
    end

    Note over U,CV: 入口 B：立即购买
    U->>CV: 点「立即购买」
    CV->>OC: router.push('/order/confirm?productId=...&quantity=...')
    OC->>OC: 读 route.query
    OC->>API: GET /api/products/:id
    API-->>OC: product

    Note over U,OC: 优惠券加载与试算
    OC->>API: GET /api/coupons/mine?status=0
    API-->>OC: 可用券列表
    U->>OC: 选券
    OC->>API: POST /api/coupons/preview { items, couponId }
    API-->>OC: { originalAmount, discountAmount, totalAmount }
    Note over U,OC: 提交订单
    U->>OC: 填收货人 + 备注 → 提交
    OC->>OC: 校验 receiver 必填
    OC->>API: POST /api/orders { items, receiver, remark, couponId? }
    API->>DB: 校验商品存在 + status=1 + stock >= quantity
    alt 校验失败
        API-->>OC: 400 (中文 message)
        OC->>U: showToast(错误)
    else 校验通过
        API->>DB: $transaction:<br/>1) product.stock -= quantity<br/>2) product.sales += quantity<br/>3) order.create(items, status=1, paidAt=now)
        DB-->>API: order (含 items)
        API-->>OC: order detail
        OC->>P: cart.clearSelected()（仅入口 A）
        OC->>OC: router.replace(`/order/success?id=${order.orderNo}`)
    end
```

### 关键校验（`ClientOrdersService.create`）

```ts
const products = await this.prisma.product.findMany({ where: { id: { in: productIds } } })
if (products.length !== productIds.length) throw new BadRequestException('部分商品不存在')

for (const item of dto.items) {
  const p = products.find((x) => x.id === item.productId)!
  if (p.status !== 1) throw new BadRequestException(`商品「${p.title}」已下架`)
  if (p.stock < item.quantity) throw new BadRequestException(`商品「${p.title}」库存不足（剩 ${p.stock}）`)
}
```

### 事务要点

`ClientOrdersService.create` 在 `prisma.$transaction(async (tx) => {...})` 中：

1. 遍历 items，对每个商品 `product.update({ stock: { decrement }, sales: { increment } })`
2. 创建 `order`（`status: 1, paidAt: now`，模拟自动支付）
3. 嵌套创建 `order_items`（含 `productTitle` / `productCover` / `price` 快照）

任一步失败，整个事务回滚。

### 演示版简化

- **跳过真实支付**：直接 `status: 1, paidAt: now`
- 订单号生成：`generateOrderNo()` = `Date.now().toString(36).toUpperCase() + 4 位随机 base36`
- 收货人结构：`{ name, phone, address }`，每次下单必填（**无地址簿**）

## 3. 确认收货流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant OD as OrderDetailView
    participant API as /api/orders/:id/confirm-receipt
    participant S as ClientOrdersService
    participant DB as PostgreSQL

    Note over U: 当前状态 = 2 (SHIPPED)
    U->>OD: 点「确认收货」
    OD->>API: POST /api/orders/:id/confirm-receipt
    API->>S: confirmReceipt(user.sub, id)
    S->>DB: 校验订单存在 + 属于当前用户 + status=2
    alt 校验失败
        S-->>API: 400 / 404
        API-->>OD: error → showToast
    else 校验通过
        S->>DB: update status=3, completedAt=now
        DB-->>S: updated
        S-->>API: order detail
        API-->>OD: 成功
        OD->>OD: 刷新列表 / 显示「已完成」
    end
```

要点：

- 仅 `SHIPPED (2)` 可确认收货；其他状态调用会抛 `BadRequestException`
- 服务端校验订单属于 `user.sub`（防越权）
- 完成时间 `completedAt = now`

## 4. 取消订单流程（客户端）

```mermaid
sequenceDiagram
    participant U as 用户
    participant OD as OrderDetailView
    participant API as /api/orders/:id/cancel
    participant S as ClientOrdersService

    Note over U: 当前状态 ∈ [0, 1] (PENDING / PAID)
    U->>OD: 点「取消订单」
    OD->>API: PATCH /api/orders/:id/cancel
    API->>S: cancel(user.sub, id)
    S->>S: 校验 status ∈ [0, 1]
    S->>S: update status=4, cancelledAt=now
    S-->>API: updated
    API-->>OD: 成功
    OD->>OD: 刷新 → 状态显示「已取消」
```

## 6. 订单快照设计

`order_items` 字段：`productTitle` / `productCover` / `price` 在下单时**直接写入**。

好处：

- 商家改商品标题 / 价格 / 封面不影响历史订单展示
- 用户看到的是「当时买的东西」
- 不需要 join 商品表也能展示订单详情

## 7. 库存与销量联动

```ts
// ClientOrdersService.create 事务
for (const item of items) {
  await tx.product.update({
    where: { id: item.productId },
    data: {
      stock: { decrement: item.quantity },
      sales: { increment: item.quantity }
    }
  })
}
```

- 下单成功：`stock -= quantity`、`sales += quantity`
- 取消订单：实际**已经恢复库存**——`ClientOrdersService.cancel` 在事务中遍历 items，对每个商品 `stock += quantity`、`sales -= quantity`，同时把订单状态改为 4 CANCELLED 并写 `cancelledAt`
- 退款：见 `11-退款与售后.md`。事务内 `markRefunded` 还原库存 + 退券 + 写 `orders.status=5 + refunded_at`
