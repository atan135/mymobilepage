# 02 服务端模块总览

> 所有 NestJS Module 的索引。每个模块按「路径前缀 / 守卫 / 关键端点」列出。

## 公共模块

### `PrismaModule`（`server/src/prisma/`）

- `PrismaService extends PrismaClient` 实现 `OnModuleInit` / `OnModuleDestroy` 自动连接 / 断开
- 在 `app.module.ts` 中 `@Global()` 注册，所有模块可直接注入无需 import

### `common/`（`server/src/common/`）

- `dto/pagination.dto.ts`：通用 `PaginationDto`（page / pageSize / keyword）与 `PaginatedResult<T>` 接口
- `filters/http-exception.filter.ts`：全局异常过滤器，统一响应结构 `{ statusCode, message, path, timestamp }`，500 级别自动打 ERROR 日志

## 前台模块详情

### `AuthModule`（`server/src/auth/`）

- 端点：
  - `POST /api/auth/login` — 公开
  - `POST /api/auth/register` — 公开
  - `GET  /api/auth/profile` — `JwtAuthGuard`
- 策略：`passport-jwt` + `JwtStrategy`（`server/src/auth/strategies/jwt.strategy.ts`）
- 装饰器：`@CurrentUser()`（`server/src/auth/decorators/current-user.decorator.ts`）取 `{ sub, username }`

### `CategoriesModule`（`server/src/categories/`）

- `GET    /api/categories`（公开，平铺列表，按 `sort asc, id asc`）
- `GET    /api/categories/:id`
- `POST   /api/categories`、`PATCH /:id`、`DELETE /:id`

### `ProductsModule`（`server/src/products/`）

- `GET /api/products`（分页，支持 `categoryId` / `keyword`，按 id desc）
- `GET /api/products/:id`
- 完整 CRUD：`POST /api/products`、`PATCH /api/products/:id`、`DELETE /api/products/:id`

> 说明：`ProductsModule` 与 `CategoriesModule` 均已在 `server/src/app.module.ts` 的 `imports` 中注册，且 `@Controller('products')` / `@Controller('categories')` 已在对应 controller 中声明。前台 `GET / POST / PATCH / DELETE /api/products` 与 `/api/categories` 均对外可访问。后台走 `@Controller('admin/products')`，命名空间天然隔离，不会冲突。

### `ClientBannersModule`（`server/src/client-banners/`）

- `GET /api/banners`（仅 `enabled = true`，按 `sort asc, id asc`，select 精简字段 `id / image / link`）

### `ClientOrdersModule`（`server/src/client-orders/`）

- 整个控制器加 `@UseGuards(JwtAuthGuard)`
- 端点：
  - `POST  /api/orders` — 创建订单（事务扣库存 + 模拟自动支付）
  - `GET   /api/orders/my` — 我的订单（分页 + 状态筛选）
  - `GET   /api/orders/:id` — 订单详情（自动校验属于当前用户）
  - `PATCH /api/orders/:id/cancel` — 取消（仅 `PENDING` / `PAID` 可取消）
  - `POST  /api/orders/:id/confirm-receipt` — 确认收货（仅 `SHIPPED` 可确认）

## 后台模块详情

### `AdminAuthModule`（`server/src/admin-auth/`）

- 端点：
  - `POST /api/admin/auth/login` — `@Public()`，公开
  - `POST /api/admin/auth/logout` — 无 token 校验（JWT 无状态，前端清掉即可）
  - `GET  /api/admin/auth/profile` — 读 `req.user.sub` 取管理员信息
- 关键组件：
  - `guards/permissions.guard.ts`：`PermissionsGuard`，**全局生效**（NestJS 在子模块里 `useGlobalGuards`），详见 `04-认证与权限体系.md`
  - `strategies/admin-jwt.strategy.ts`：`passport-jwt` 策略（仅保留以兼容未来扩展，当前守卫用 `JwtService` 直验）
  - `decorators/require-permission.decorator.ts`：`@RequirePermission('user:list')` 等
  - `decorators/public.decorator.ts`：`@Public()` 标记不走守卫的端点

### `AdminUsersModule`（`server/src/admin-users/`）

- `GET    /api/admin/users` — 列表（分页 + 状态筛选 + 关键字模糊搜索 username / nickname / phone）
- `GET    /api/admin/users/:id` — 详情（含 `_count.orders`）
- `PATCH  /api/admin/users/:id` — 更新（启/禁用、改昵称/手机号）

### `AdminCategoriesModule`（`server/src/admin-categories/`）

- `GET    /api/admin/categories` — 列表（含 `_count.products`）
- `GET    /api/admin/categories/:id`
- `POST   /api/admin/categories` — 名称冲突抛 `ConflictException`
- `PATCH  /api/admin/categories/:id`
- `DELETE /api/admin/categories/:id` — 分类下还有商品时拒绝

### `AdminProductsModule`（`server/src/admin-products/`）

- `GET    /api/admin/products` — 列表（多条件筛选：分类 / 状态 / 价格区间 / 关键字）
- `GET    /api/admin/products/:id`
- `POST   /api/admin/products`
- `PATCH  /api/admin/products/:id`
- `PATCH  /api/admin/products/:id/status` — 上下架（status 0/1）
- `PATCH  /api/admin/products/:id/stock` — 库存调整
- `DELETE /api/admin/products/:id`

### `AdminBannersModule`（`server/src/admin-banners/`）

- `GET    /api/admin/banners` — 全部（含 disabled）
- `GET    /api/admin/banners/:id`
- `POST   /api/admin/banners`
- `PATCH  /api/admin/banners/:id`
- `DELETE /api/admin/banners/:id`

### `AdminAnnouncementsModule`（`server/src/admin-announcements/`）

- `GET    /api/admin/announcements`
- `GET    /api/admin/announcements/:id`
- `POST   /api/admin/announcements`
- `PATCH  /api/admin/announcements/:id`
- `PATCH  /api/admin/announcements/:id/publish` — 发布（写 `publishedAt`）
- `PATCH  /api/admin/announcements/:id/unpublish` — 下架
- `DELETE /api/admin/announcements/:id`

### `AdminOrdersModule`（`server/src/admin-orders/`）

- `GET    /api/admin/orders` — 列表（状态筛选 + 关键字搜索 订单号 / 用户名）
- `GET    /api/admin/orders/:id` — 详情（含收货人反序列化）
- `PATCH  /api/admin/orders/:id/status` — 通用状态切换（沿状态机表）
- `PATCH  /api/admin/orders/:id/ship` — 发货（写入 shipCompany / shipNo + shippedAt）

状态机（`server/src/admin-orders/dto/order.dto.ts`）：

```ts
export const ORDER_TRANSITIONS: Record<OrderStatus, OrderStatus[]> = {
  0: [1, 4],   // PENDING  → PAID / CANCELLED
  1: [2, 4],   // PAID     → SHIPPED / CANCELLED
  2: [3],      // SHIPPED  → COMPLETED
  3: [],       // COMPLETED → 终态
  4: []        // CANCELLED → 终态
}
```

### `AdminDashboardModule`（`server/src/admin-dashboard/`）

- `GET /api/admin/dashboard/overview` — 聚合今日订单数 / 今日 GMV / 总用户数 / 待处理订单数 / 热销 Top10 / 待处理 Top5
- `GET /api/admin/dashboard/sales-trend?days=1..30`（默认 7）— 按天聚合 GMV + 订单数
- 权限：`dashboard:view`

## 路由前缀约定总结

| 控制器 | 完整前缀 |
| --- | --- |
| 前台任意模块 | `/api/<path>` |
| 后台任意模块 | `/api/admin/<path>` |

通过 `app.setGlobalPrefix('api')`（main.ts） + 各模块 `@Controller('admin/xxx')` 形成。

## 全局守卫覆盖范围

`PermissionsGuard` 内部判断：

```ts
if (!req.path.startsWith('/api/admin')) return true
```

因此**仅后台接口**会被强制校验 Token + 权限。前台接口是否要登录由各控制器自己用 `@UseGuards(JwtAuthGuard)` 决定（目前只有 `ClientOrdersController` 加了）。详见 `04-认证与权限体系.md`。
