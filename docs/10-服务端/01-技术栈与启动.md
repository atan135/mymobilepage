# 01 服务端技术栈与启动

> `server/` 子项目的技术栈、环境变量、构建命令速查。

## 1. 技术栈

| 维度 | 选型 |
| --- | --- |
| 框架 | NestJS 12（Express 适配器） |
| 语言 | TypeScript 5 |
| ORM | Prisma 6（`@prisma/client`） |
| 数据库 | PostgreSQL（`provider = "postgresql"`） |
| 认证 | `@nestjs/jwt`（两套独立 secret） |
| 校验 | `class-validator` + `class-transformer`（全局 `ValidationPipe`） |
| 安全 | `helmet` 默认中间件 |
| 跨域 | `@nestjs/common` 的 `enableCors` |
| 日志 | NestJS 内置 `Logger` |
| 全局异常 | `HttpExceptionFilter`（`server/src/common/filters/`） |

### 关键依赖

- `bcryptjs`：管理员密码哈希（seed 与登录比对）
- `@prisma/client`：Prisma 生成的类型化客户端
- `helmet`：HTTP 安全头
- `@nestjs/config`：`.env` 加载（`isGlobal: true, cache: true`）

## 2. 入口与全局设置

文件：`server/src/main.ts`

```ts
const app = await NestFactory.create(AppModule, { bufferLogs: true })

app.use(helmet())
app.enableCors({
  origin: (process.env.CORS_ORIGINS ?? 'http://localhost:5173')
    .split(',').map((s) => s.trim()).filter(Boolean),
  credentials: true
})

app.setGlobalPrefix('api')
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,
  forbidNonWhitelisted: true,
  transform: true
}))
app.useGlobalFilters(new HttpExceptionFilter())

const port = Number(process.env.PORT ?? 3000)
await app.listen(port, '0.0.0.0')
```

含义：

- `bufferLogs: true`：在 `app.useLogger` 之前缓存日志
- `helmet()`：默认安全头（X-Frame-Options 等）
- CORS：默认 `http://localhost:5173`，可通过 `CORS_ORIGINS` 加白名单（逗号分隔）
- 全局 `/api` 前缀
- `ValidationPipe` 三个关键开关：`whitelist`（去掉未声明字段）、`forbidNonWhitelisted`（未声明字段直接 400）、`transform`（自动 `class-transformer`）
- 监听 `0.0.0.0` 以便容器 / 局域网访问

## 3. 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | （必填） | Prisma 连接串，例如 `postgresql://user:pwd@localhost:5432/mymobilepage` |
| `PORT` | `3000` | 服务监听端口 |
| `CORS_ORIGINS` | `http://localhost:5173` | 允许跨域的 origin，多个用逗号分隔 |
| `JWT_SECRET` | （必填，建议显式） | 前台 Token 签名密钥 |
| `JWT_ADMIN_SECRET` | `dev-admin-secret`（兜底） | 后台 Token 签名密钥，**与前台必须不同** |
| `JWT_EXPIRES_IN` | `7d` | 前台 Token 有效期 |
| `JWT_ADMIN_EXPIRES_IN` | `7d` | 后台 Token 有效期 |

> 后台 secret 在 `PermissionsGuard` 与 `admin-jwt.strategy.ts` 中读取，**两个 secret 必须不同**才能保证前后台权限隔离。

## 4. 启动 / 构建命令

通过根 `package.json` 的 workspaces 调用：

```bash
# 开发（watch 模式，自动重载）
npm run dev:server

# 类型检查
npm run type-check:server

# 构建（产物到 server/dist）
npm run build:server

# 运行构建产物
npm run start:server
```

子项目内等价命令（`server/package.json`）：

```bash
npm run start:dev      # 等价 npm run dev:server
npm run start:prod     # 等价 npm run start:server
npm run build
npm run type-check
npm run prisma:migrate
npm run prisma:seed
npm run prisma:studio
```

## 5. Prisma 命令

```bash
# 开发期：创建迁移 + 应用 + 重生成 client
npm run prisma:migrate
# 等价于：npx prisma migrate dev

# 仅重新生成 client（schema 改完没改迁移时用）
npm run prisma:generate

# 可视化数据库（默认 http://localhost:5555）
npm run prisma:studio

# 重置并写入初始数据（会清空业务表！）
npm run prisma:seed
```

> `prisma:seed` 在 `server/package.json` 里配置：
> ```json
> "prisma": {
>   "seed": "ts-node prisma/seed.ts"
> }
> ```

详见 `06-数据迁移与Seed脚本.md`。

## 6. 目录约定

```
server/src/
├── main.ts                  入口（Helmet + CORS + ValidationPipe + 过滤器）
├── app.module.ts            根模块（注册 14 个业务模块）
├── prisma/                  PrismaService（@Global）
├── common/                  通用 dto / filters
├── auth/                    前台 JWT（passport-jwt 策略 + JwtAuthGuard）
├── users/                   前台用户模块（service only，路由尚未挂）
├── categories/              前台公开分类
├── products/                前台公开商品
├── client-banners/          前台轮播图（GET 公开）
├── client-orders/           前台订单（JwtAuthGuard）
├── admin-auth/              后台登录 + PermissionsGuard + admin-jwt 直验
├── admin-users/             后台用户管理
├── admin-categories/        后台分类管理
├── admin-products/          后台商品管理
├── admin-banners/           后台轮播图管理
├── admin-announcements/     后台公告管理
├── admin-orders/            后台订单管理（含状态机）
└── admin-dashboard/         后台仪表盘聚合
```

## 7. 启动顺序建议

1. 先 `npm install`（根目录）
2. 配置 `server/.env`
3. `npm run prisma:migrate` 创建表
4. `npm run prisma:seed` 写入初始数据
5. `npm run dev:server` 启动后端
6. 再分别启动 `dev:admin` 与 `dev:client`

详见 `00-总览与入门/02-快速开始.md`。
